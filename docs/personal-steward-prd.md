# 个人管家 PRD

| 项目 | 内容 |
| --- | --- |
 | 文档版本 | V1.2（立项评审稿，已完成技术可行性审查与产品策略补充） |
| 产品名称 | 自明 |
| 目标设备 | Android 手机（vivo X300 Pro）与 Windows 笔记本 |
| 目标用户 | 单一的个人用户本人 |
| 文档范围 | 产品目标、范围、信息架构、页面与交互流程、业务规则、验收标准；不包含技术实现方案 |
| 需求优先级 | P0 为首个可用版本，P1/P2 为立项后续范围 |

## 1. 立项结论与产品定义

建议立项，但以“每天能够持续使用”作为首要验证目标：先做跨设备计划管理、手动记账与会员管理，再逐步扩展支付自动识别、资产、投资和运动数据。

自明是一个仅服务于用户本人的跨设备生活管理工具。它以“今天”为统一入口，把当天要做的事、可专注的时间、已发生的消费、即将续费的会员、个人资产和运动情况汇集在一起。手机用于随手记录、接收提醒和确认自动发现的信息；Windows 用于查看全貌、批量整理和分析。两端同一账号下的数据应保持一致。

### 1.1 要解决的问题

1. 计划、便签、倒计时分散在多个工具中，用户无法在同一处决定“现在该做什么”。
2. 手机支付后往往不记账，月底只能模糊地知道自己花了钱，无法追溯消费去向。
3. 包月、包年服务容易遗忘续费时间，用户不知道持续使用的真实成本。
4. 贵重物品购买后缺少价值、保修和处置记录，难以判断个人资产的真实状态。
5. 投资与运动数据分散，用户需要一个能记录、查看汇总且不作投资或医疗判断的个人面板。

### 1.2 成功标准

首个可用版本上线后，以下结果用于判断产品是否值得继续投入：

| 指标 | 目标 |
| --- | --- |
| 每日计划使用 | 用户可在 1 分钟内完成当天任务查看、完成或调整 |
| 记账完整性 | 用户可在支付后 30 秒内完成一笔手动记账；待确认账单可被明确处理，不出现“无处可去”的记录 |
| 会员提醒有效性 | 到期前的提醒可被查看、延期、续费、停用或忽略 |
| 跨端一致性 | 在任一端新增、修改、完成的 P0 数据，在另一端可见且状态明确 |
| 数据可理解性 | 所有金额、估值、收益、运动统计均展示统计口径及最近更新时间 |

## 2. 用户、场景与范围

### 2.1 用户角色

一期只有“本人”一个角色，不涉及家庭成员、共同账本、委托代理或多人协作。用户拥有所有数据的查看、修改、导出和删除权。

### 2.2 典型使用场景

| 场景 | 用户动作 | 期望结果 |
| --- | --- | --- |
| 早晨安排 | 打开“今天”，查看任务、时间块和提醒 | 知道今天最重要的事情及空闲时间 |
| 临时插入事项 | 在手机上快速新增“17:00 取快递” | 任务进入今天日程，并在设定时间提醒 |
| 支付后记账 | 收到支付信息或手动输入金额 | 得到一笔待确认或正式账单，可补全分类 |
| 月末复盘 | 在 Windows 上查看当月支出、会员与资产变化 | 理解钱花在哪里、哪些费用即将发生 |
| 专注工作 | 从任务详情启动番茄钟 | 专注记录自动归入该任务 |
| 管理续费 | 收到会员到期提醒 | 可选择续费、取消、暂停或推迟处理 |
| 查看健康概览 | 打开运动页面 | 看到当天步数、运动时长和周/月趋势；缺失数据被明确标记 |

### 2.3 范围边界

**本 PRD 要求的能力**：计划与日历、便签、番茄钟、倒计时、四象限、跨端同步、手动记账、支付信息形成待确认账单、消费分析、会员、贵重物品折旧、投资台账、基础运动统计。

**明确不做或不承诺的能力**：

- 不直接操作、读取或保存微信、支付宝、京东等第三方账号密码、验证码及完整页面内容。
- 不承诺获取任意支付平台、京东黄金或 vivo 运动应用的完整数据；无合法稳定来源时，必须提供手动录入或文件导入替代路径。
- 不提供自动交易、买卖建议、收益承诺、医疗建议或健康诊断。
- 不包含多人共享、报销、借贷、发票报税、家庭资产合并、实时行情交易功能。
- 不要求用户为了记账而开放与目标无关的权限；用户可以随时关闭某一数据源。

## 3. 产品结构与通用规则

### 3.1 主导航

手机底部导航和 Windows 左侧导航均包含：**今天、计划、账本、资产、分析、设置**。手机在主界面提供“新增”浮动按钮；Windows 在各模块顶部提供“新增”和筛选入口。

| 一级入口 | 核心内容 |
| --- | --- |
| 今天 | 当日时间表、待办、专注入口、待确认账单、到期提醒、运动摘要 |
| 计划 | 日历、任务清单、便签、四象限、番茄钟记录、倒计时 |
| 账本 | 账单、待确认、分类、账户、预算和消费统计 |
| 资产 | 会员、贵重物品、投资台账 |
| 分析 | 消费、会员、物品折旧、投资、运动的可筛选汇总 |
| 设置 | 账号、同步状态、提醒、数据来源、权限、分类、导入导出与数据删除 |

### 3.2 跨端交互原则

1. 两端的信息结构与字段含义相同，但手机优先单手快速完成，Windows 优先高密度浏览与批量编辑。
2. 所有可同步项目显示最近修改时间；网络不可用时，保存成功应显示“待同步”，而不是假装已在另一端更新。
3. 同一字段发生冲突时，系统不得静默覆盖涉及金额、交易、投资和删除的内容；用户需在“同步冲突”页选择保留版本或手动合并。普通任务标题、描述等内容可按最后一次确认保存的版本展示，并保留修改历史入口。
4. 删除先进入回收站。用户可恢复；永久删除必须二次确认，并说明会删除的内容范围。
5. 金额均显示币种；日期时间以用户当前时区展示。分析报表默认按自然月统计，用户可改为自定义区间。

### 3.3 “今天”工作台

“今天”不是另一套数据，而是各模块的聚合视图。由上至下依次为：日期与天气占位（非本期必需）、今日进度、时间轴、未安排任务、待确认账单、提醒、运动摘要。

交互规则：

1. 用户点击日期可切换至任意一天；非今天日期顶部显示“返回今天”。
2. 时间轴只显示已安排开始/结束时间的任务；全天任务置于顶部；重叠任务以并排卡片显示并标出冲突。
3. 未安排任务按四象限与优先级排序。用户可长按拖入时间轴，或点击“安排时间”。
4. 待确认账单卡片显示来源、金额、商户/订单摘要与识别时间；点击进入确认页。若超过 24 小时仍未处理，卡片保留但不重复打扰。
5. 到期提醒显示“距到期 N 天”，可直接执行“查看”“推迟提醒”；续费或取消必须进入详情页确认。
6. Windows 支持将今日任务、待确认账单以列表形式多选处理；手机一次以单条处理为主。

## 4. 计划与时间管理

### 4.1 任务

#### 4.1.1 创建与编辑

用户从任意页面点击“新增任务”后，先进入轻量输入框：输入标题并保存即可创建“收集箱任务”。展开“更多设置”后可填写以下字段。

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填，1–100 字；空标题不可保存 |
| 描述 | 选填，支持多段文本与清单式子项 |
| 清单 | 默认“收集箱”，可新建或选择自定义清单 |
| 日期与时间段 | 可不填；填开始时间时可选择结束时间或预计时长；结束不得早于开始 |
| 全天 | 开启后不显示具体时刻，与时间段互斥 |
| 重复 | 不重复、每日、每周、每月、工作日及自定义；修改单次实例时必须选择“仅此一次”或“本次及以后” |
| 四象限 | 重要且紧急、重要不紧急、不重要但紧急、不重要不紧急；默认未归类 |
| 优先级 | 高、中、低、无；仅影响排序，不替代四象限 |
| 提醒 | 可设一个或多个提醒；无日期的任务不可设置绝对时间提醒 |
| 子任务 | 可新增、排序和勾选；父任务完成时若存在未完成子任务，应提示“同时完成全部子任务”或“保留子任务” |
| 关联便签 | 可新建便签或关联已有便签 |

保存后，界面反馈“已保存”及同步状态。用户可撤销刚刚的删除、完成、移动等单步操作。

#### 4.1.2 任务状态与完成

任务状态为：收集箱、已安排、进行中、已完成、已取消、已归档。用户勾选任务即标记完成；完成项默认在当天底部折叠显示。重复任务完成后，仅完成当前实例，系统生成下一次实例。已完成任务允许“恢复未完成”，恢复后保留原实际完成时间于历史记录。

若任务有时间段，用户拖动到另一天或另一时段时，系统先显示新的时间；若与既有任务重叠，出现非阻断提示“与 X 个任务重叠”，用户可继续保存、取消，或查看冲突任务。

#### 4.1.3 日历视图

计划模块提供月、周、日三种视图：

- 月视图用于看日期是否有安排，每日最多显示三条任务和“还有 N 项”。点击日期进入日视图。
- 周视图以 0:00–24:00 时间轴展示时间段任务，全天任务单列。Windows 支持拖拽调整日期/时段；手机通过长按后拖动调整。
- 日视图显示完整时间轴、全天任务和未安排任务。点击空白时段预填开始时间创建任务。

### 4.2 便签

便签用于保存资料、想法和清单，不能被“完成”。便签字段包括标题、正文、标签、关联任务、创建/更新时间和置顶状态。

用户可从计划页新建便签，或在任务详情中“关联便签”。关联后，任务详情显示便签标题和摘要；删除便签前须提示是否解除关联。便签可置顶、归档、搜索，正文关键词应能被标题搜索结果命中。附件、图片和网页收藏不纳入本期必做范围；若后续增加，需单独定义容量与隐私规则。

### 4.3 四象限面板

面板固定显示四个象限。每张任务卡显示标题、日期、是否逾期、预计时长和完成状态。用户可拖动任务卡到另一象限；移动后只更新“重要性/紧急性”归类，不修改日期和优先级。

未归类任务位于面板顶部的“待分配”抽屉，用户可拖入象限。已完成任务默认不展示，可通过筛选开启。四象限为空时展示说明和“添加任务”按钮。

### 4.4 番茄钟与专注记录

#### 4.4.1 启动流程

1. 用户从今天、任务详情或计划页点击“开始专注”。
2. 若从任务启动，自动关联该任务；若从独立入口启动，用户可选择任务或“无关联专注”。
3. 用户选择预设时长（默认 25 分钟）或自定义本次时长，点击开始。
4. 计时页面显示剩余时间、关联任务、暂停、结束和放弃。退出页面后，计时状态在今天页持续可见。
5. 结束时用户选择“完成一个番茄”“提前结束并记录实际时长”或“放弃且不计入统计”。
6. 有效记录进入任务详情和专注历史；不自动完成任务。

暂停累计时间不计入专注时长。任务已完成时仍可发起专注，但需提示“该任务已完成，是否继续记录”。用户可在设置中配置默认工作、短休息、长休息时长和每轮后的提醒；不要求本期实现强制休息。

### 4.5 倒计时

倒计时适用于明确截止时点，例如“距离签证到期还有 30 天”。用户输入名称、目标日期时间、提醒时点和是否重复。页面显示剩余天/时/分；到期后变为“已到期”，不自动删除。

用户可在到期提醒中执行“完成/关闭”“延后目标时间”“重新开始”。重复倒计时在本次关闭后按规则生成下一次。倒计时与任务可互相关联，但独立存在。

### 4.6 计划模块验收

1. 用户可在手机和 Windows 创建、编辑、完成、取消、恢复任务，并在另一端看到相同状态。
2. 日、周、月视图能正确展示全天任务、时间段任务与未安排任务；重叠安排有可见提示。
3. 重复任务完成当前实例不会改变已完成历史，且按规则生成下一实例。
4. 用户可通过任务详情启动并结束番茄钟，专注时长可在任务和历史中查看。
5. 用户可在四象限中移动任务，且移动不改变任务日期。

## 5. 账本与消费分析

### 5.1 账本对象和状态

一笔账单包含：交易类型（支出、收入、转账、退款）、金额、币种、交易时间、商户/对方、分类、账户、平台、标签、备注、凭证、来源及状态。

账单状态为：**待确认、已入账、已忽略、已删除**。只有已入账账单参与消费统计、预算、会员关联与资产关联。退款可关联原支出；关联后分析中应显示净额，原账单仍保留原始金额与退款关系。

### 5.2 手动记账流程

1. 用户点击“记一笔”，默认选择支出并聚焦金额输入。
2. 输入金额后，系统展示最近使用的分类、账户和商户供一键选择。
3. 用户补充交易时间（默认当前时间）、分类、账户、平台、商户、标签或备注；转账必须选择转出与转入账户，且不计入收入/支出。
4. 用户点击保存，账单直接成为“已入账”。
5. 保存成功页提供“继续记账”“查看账单”“撤销”操作。

金额必须大于零；负数不作为输入方式。退款通过交易类型标识而非输入负金额。若用户从会员或贵重物品详情发起记账，则预填关联对象但仍可修改。

### 5.3 支付信息识别与待确认流程（P1）

支持的来源范围为微信、支付宝、云闪付、淘宝、京东、抖音、拼多多、美团等应用中**用户授权且可获得的支付相关信息**。产品表现为“自动发现候选账单”，不是承诺完整自动记账。

1. 用户在设置中阅读用途说明，分别选择开启哪些来源；未授权来源不得显示为“已连接”。
2. 识别到可能的支付、退款或转账信息时，系统生成待确认账单，带来源、识别时间、金额、商户摘要及置信提示。
3. 用户点击待确认卡片，进入确认页。页面突出金额和类型，并展示可编辑的时间、分类、账户、商户、标签和备注。
4. 系统若发现与已入账账单在金额、时间、商户上高度相似，显示“可能重复”，并让用户选择“仍然入账”“合并为现有账单”“忽略此记录”。不得自动合并或自动删除。
5. 用户选择“确认入账”后，账单参与统计；选择“忽略”后记录保留在忽略列表，可恢复；选择“稍后处理”则仍停留在待确认。
6. 用户可在设置中关闭某个平台来源、清空未确认原始摘要，或撤销授权。关闭后不影响已入账数据。

识别失败、金额缺失或无法判断交易类型时，待确认项必须显示“信息不完整”，用户可补全后入账或忽略。不得把模糊信息自动写入正式账本。

### 5.4 账单列表、分类和预算

账单列表默认按交易时间倒序，支持按日期、收支类型、分类、账户、平台、标签、状态和金额区间筛选。点击账单查看完整信息、来源与关联对象；用户可编辑、复制、删除或标记为退款。

分类采用“一级分类/二级分类”结构。系统提供餐饮、交通、购物、居住、通信、娱乐、医疗健康、学习、礼物、人情往来、其他等默认分类；用户可新增、改名、归档自定义分类。归档分类不能用于新账单，但历史账单保留原分类。

预算（P1）以月为周期，用户可为总支出或某一级分类设定额度。预算页显示“已使用/预算/剩余”，退款抵扣已使用金额，转账不参与。超出 80% 和超支时，按用户设置提醒一次；未设置预算则不显示“超支”。

### 5.5 消费分析

分析页默认展示本月：总支出、总收入、净现金流、日均支出、分类占比、日趋势、账户/平台分布和较上月变化。所有卡片都可点击进入对应账单明细。无数据时显示“本周期暂无已入账账单”，不将缺失误显示为零消费。

用户切换日期区间后，所有图表和汇总同步变化。统计口径需明确：支出按已入账支出减去已关联退款计算；转账不计入收支；待确认和已忽略不参与。

### 5.6 账本模块验收

1. 用户可在 30 秒内完成最少字段的支出或收入记账，并在列表与分析中看到结果。
2. 待确认账单在用户确认前不计入统计；确认、忽略、恢复和重复处理均有明确入口。
3. 原支出与退款关联后，分析显示正确净额且两笔原始记录可追溯。
4. 任何图表均可钻取到账单明细，并说明日期范围和统计口径。

## 6. 会员与周期性消费

### 6.1 会员信息

会员可用于视频、音乐、云盘、软件、健身、通信套餐、保险等固定周期费用。字段包括名称、服务商、图标/分类、费用、币种、计费周期、当前周期开始/结束日期、是否自动续费、扣款账户、关联账单、提醒规则、状态和备注。

状态为：使用中、已暂停、已取消、已到期。已取消代表不再预期续费；已到期代表当前服务期结束且尚未续费。

### 6.2 创建、续费与到期处理

1. 用户点击“新增会员”，填写名称、费用、周期和本周期开始日期；系统根据周期推算结束日期，用户可手动修正。
2. 用户设置自动续费状态与提醒日（默认到期前 7 天、3 天、1 天）。
3. 保存后，会员进入资产页会员列表，并在今天页于提醒窗口出现。
4. 到期提醒点击后进入详情，用户选择：续费、取消自动续费、暂停、标记已取消、推迟提醒。
5. 选择续费时，用户输入本次实际支付金额和新周期，系统保留上一周期历史，可选创建或关联账单。
6. 选择暂停或取消时，未来提醒停止；历史费用和周期保留。

### 6.3 成本计算与展示

会员详情显示本周期已支付金额、服务天数、已使用天数、剩余天数、平均日花费、预计月成本和预计年成本。平均日花费口径为：**本周期已支付金额 ÷ 当前周期实际天数**；若尚未开始或金额缺失，则显示“暂无计算条件”。“已使用天数成本”可另显示为已支付金额 ÷ 已使用天数，但必须清晰标注，不能与平均日花费混淆。

会员列表支持按到期时间、费用、状态筛选；到期前 30 天默认优先排序。初期不把“使用频率低”作为自动停用依据，除非用户手动记录使用次数；产品不能凭空判断会员闲置。

### 6.4 会员模块验收

1. 创建周期性会员后，系统正确计算到期日、日均成本、预计月/年成本。
2. 续费生成新周期且保留历史；取消或暂停停止未来提醒。
3. 会员可关联账单，关联账单不重复计入会员总费用。

## 7. 贵重物品与折旧

### 7.1 物品档案

适用于手机、电脑、相机、镜头、手表、首饰、家电、乐器和收藏品。字段包括名称、分类、品牌、型号、序列号（选填）、购买价格、购买日期、购买渠道、照片/凭证（后续能力）、保修截止日期、持有状态、关联账单、折旧方式与估值记录。

持有状态为：持有中、已出售、已转赠、已报废。非“持有中”的物品不计入当前持有资产总值，但在历史中保留。

### 7.2 折旧和估值流程

1. 用户新增物品并填写购买价格、购买日期与预计使用年限。
2. 用户选择折旧方式：直线折旧、按残值率折旧或手动估值。产品在选项旁用简短例子说明差异。
3. 选择直线折旧时需填写残值或残值率；选择按残值率时需填写年度残值率；选择手动估值时需填写当前估值和估值日期。
4. 保存后，物品详情展示购买价、累计折旧、当前账面估值、计算日期和方法。估值必须标记为“估算，不代表实际成交价”。
5. 用户可以新增一条市场估值记录，填写估值、日期、来源说明；手动估值优先展示最新有效记录。
6. 用户处理出售、转赠或报废时，输入处理日期与出售金额（如有），确认后停止后续折旧，保留处置记录。

折旧从购买日期起算；未来购买日期不能保存。预计使用年限必须大于零。若计算出的估值低于残值，下限保持残值。购买价未知时可先建档，但不计算折旧，提示补充金额。

### 7.3 物品模块验收

1. 用户可以创建、查看、编辑和结束一件物品的持有状态。
2. 不同折旧方式有可解释的字段和结果，系统不把估值表述为市场成交价。
3. 处置后的物品不进入当前持有总值，但历史记录、折旧和关联账单仍可查看。

## 8. 投资理财信息汇总

### 8.1 产品定位和数据边界

投资模块是“个人投资记录与汇总面板”，不提供交易指令、推荐、风险评级或投资建议。支持黄金（含京东黄金的手动台账）、基金、股票、银行理财、债券、现金及自定义品类。

对于京东黄金：本期只支持用户手动录入、导入用户自行取得的交易记录，或在存在明确、稳定、合规授权方式后才展示连接能力。页面不得承诺“自动抓取京东数据”，也不得引导用户提供京东密码或验证码。

### 8.2 账户、标的与交易

1. 用户先新增投资账户，填写名称、平台（可选“京东”）、账户类型和币种。
2. 用户在账户内新增标的，填写名称、品类、代码/单位（选填）和初始持仓；也可直接从“记录交易”创建标的。
3. 交易类型包括买入、卖出、定投、分红、费用、转入、转出、估值调整。每笔需填写日期、数量、成交单价、费用和备注；不同品类可隐藏无意义字段，但应保留可追溯金额。
4. 用户定期更新标的当前单价和价格日期，或导入可验证的价格记录。没有最新价格时，持仓卡显示“待更新”，并显示最后价格日期。
5. 系统基于交易和最新价格展示成本、市值、持仓数量、浮动盈亏、已实现收益和收益率；每项均可进入明细核对。

卖出数量不能超过已记录可用持仓；若用户确有历史缺失，可先使用“初始持仓调整”补录，而非允许负持仓。费用单独记录并计入收益计算。现金账户不因没有行情而显示待更新。

### 8.3 投资汇总与验收

资产页投资区域显示总成本、总市值、浮动盈亏、最近更新日期和品类占比。用户可按账户、品类、标的和日期筛选；任何汇总可追溯至交易列表与价格记录。

验收标准：

1. 用户可不连接第三方账号，完整记录一笔京东黄金或其他投资品的买入、卖出与估值。
2. 无最新价格时不伪造实时市值，必须展示数据过期状态。
3. 汇总结果能查看构成明细；产品页面不出现买卖建议或收益承诺。

## 9. 运动统计

### 9.1 范围与数据状态

一期仅聚合步数、运动时长、距离、消耗热量和运动类型，并提供日、周、月趋势。数据为生活记录，非医疗数据；不提供诊断、训练处方或异常判断。

用户可通过手机中可授权的数据来源同步，或手动补录。对 vivo 运动信息，只有当用户设备上存在可授权且能够提供相应数据的来源时才可同步；否则展示“当前无法获取，可手动补录”，不得声称已与 vivo 运动直连。

每条或每组统计数据应有状态：已同步、手动录入、数据缺失、可能重复。数据来源、最后同步时间和覆盖时间范围必须在详情可见。

### 9.2 授权、同步与补录流程

1. 用户首次进入运动页，看到数据用途说明和“连接运动数据”按钮，也可跳过并使用手动记录。
2. 用户选择授权数据项（步数、运动记录、距离、热量等），可随时取消某一项。未授权项不显示为零，而显示“未授权/暂无数据”。
3. 同步完成后展示同步摘要：新增记录数量、覆盖日期、来源和是否存在可能重复。
4. 若同一时段存在多个来源，系统在详情页提示来源；聚合数据优先避免重复累计。无法判断时应标记“可能重复”，供用户选择保留来源或隐藏某条记录。
5. 用户点击“手动记录”可填写日期、运动类型、时长、距离、热量和备注。手动记录带明显标签，不覆盖原始同步记录。
6. 用户在设置中可断开数据来源；断开后停止新同步，历史数据可选择保留或删除。

### 9.3 展示与验收

今天页只显示步数、运动时长和目标进度（用户设置目标后）；运动页显示日趋势、周/月汇总、运动类型分布和记录列表。无数据、未授权、同步失败三种情况必须有不同说明和可执行入口。

验收标准：用户能在无任何外部同步条件下手动记录一次运动；在有可用授权来源时查看来源与最近同步结果；多来源数据不会被无提示地重复相加。

## 10. 提醒、搜索、同步和数据管理

### 10.1 提醒中心

提醒包括任务、倒计时、会员到期、预算阈值和待确认账单。系统提醒到达后提供与场景匹配的快速操作：任务可“完成/稍后提醒”，会员可“查看/推迟”，账单可“确认/忽略/稍后”。

用户可以设置免打扰时段；免打扰期间非紧急提醒汇总至结束后展示。逾期任务不应每天无限重复提醒，默认只在到期时与次日早晨提示一次，用户可自行调整。

### 10.2 搜索与筛选

全局搜索覆盖任务标题与描述、便签标题与正文、账单商户/备注、会员名称、物品名称和投资标的。搜索结果按内容类型分组，点击进入详情。金融敏感原始信息不在全局搜索结果中完整展示。

### 10.3 同步状态与异常处理

设置页提供同步状态页，显示最近成功同步时间、待同步项目数量、失败项目数量和“立即重试”。用户在离线时新增或编辑内容，界面应标记“仅本机，等待同步”；恢复后状态变为“已同步”或“需要处理”。

发生冲突时，用户进入冲突处理页，逐条对比“本机版本”和“另一端版本”的修改时间与内容：

- 普通任务、便签：可保留任一版本或合并文本。
- 金额、账单、投资交易：可保留其一或保留为两条并标记待核对；默认不自动覆盖。
- 删除与编辑冲突：先提示恢复/删除选择，不能默默删除用户刚编辑的内容。

### 10.4 数据导入、导出与删除

用户可导出自己已入账账单、任务、会员、物品和投资交易；导出前选择数据范围与文件类型。导入仅适用于用户自行拥有且有权使用的文件，导入预览需显示总行数、可导入数、字段映射异常和疑似重复数，用户确认后才写入。

用户可在设置中执行：删除单项数据、清空某模块数据、导出全部数据、删除账号及全部数据。涉及全部数据的操作必须展示范围、要求再次确认，并说明删除后无法从产品内恢复的后果。

### 11.2 P1：自动化与资产管理

支付信息形成待确认账单、账单文件导入与重复提示、预算、贵重物品与折旧、投资手动台账及价格更新、完整分析页。

### 11.3 P2：健康与增强能力

可授权运动数据同步、手动运动补录、运动趋势、周报/月报，以及在明确数据来源和用户同意的前提下评估更多导入能力。

1. P0 全部核心流程均可在手机和 Windows 完成；两端至少经过一次离线新增、恢复连接后的同步验证。
2. 不存在把待确认账单、未授权运动数据或无价格投资错误计入正式统计的情形。
3. 所有不可用的数据源都有替代路径和清晰提示，不使用“已同步”“自动抓取”等误导性文案。
4. 提醒、删除、同步冲突、金额编辑等高影响操作均有明确反馈与可追溯入口。
5. 产品内明确说明投资和运动模块的非建议、非医疗定位。

## 12. 立项待确认项

以下事项会影响范围和优先级，但不阻碍先按 P0 设计：

1. 数据仅本人使用，还是未来需要家庭成员/共同账本？
2. 是否接受账号同步，还是必须以本地数据为主？
3. 用户是否需要预算、借贷、报销、发票等更完整的财务场景？
4. 贵重物品的照片、发票等凭证是否需要在首期保存？
5. 投资价格是仅手动更新，还是后续需要引入可授权的行情来源？
6. vivo 设备上实际可供用户授权的运动数据来源和字段范围是什么？

> 本文档以“先确保用户能可靠记录与理解自己的数据”为产品基线。第三方支付、京东黄金与 vivo 运动信息只在用户可控、来源明确时进入产品流程；数据不可得时，以手动录入或用户自行导入为准。

## 13. 技术可行性约束与实现前门槛

本 PRD 定义产品需要做到什么；实现可行性审查与证据见 [技术可行性审查](personal-steward-technical-feasibility-review.md)。除 P0 的核心手工能力外，所有外部数据能力均以“可授权、可验证、可关闭”为前提，不得以页面文案或计划名称替代真实验证。

### 13.1 交付边界

1. **支付来源**：微信、支付宝、云闪付、淘宝、京东、抖音、拼多多和美团仅在目标设备上确有可解析的用户授权通知时，才支持生成待确认账单；不承诺完整流水、全量覆盖或自动入账。
2. **京东黄金**：一期/二期支持手工录入与用户自行取得文件的导入；未确认稳定、合规的个人账户接口前，不提供“自动抓取”或账号登录入口。
3. **vivo 运动**：只有在 vivo X300 Pro 上能通过用户授权的数据源读取到相应数据时才同步；否则保留手动补录，不读取 vivo 私有应用页面或使用无障碍服务自动化。
4. **提醒**：用户拒绝系统通知权限、关闭通知或系统限制后台时，产品必须显示影响与重新开启路径；不得承诺绝对准时提醒。

### 13.2 P0 上线前新增验收

1. Android 与 Windows 在两端均离线编辑任务、便签和一笔手工账单后，恢复网络可按第 10.3 节规则同步，冲突和失败项目可追溯。
2. 用户可在两端导出自己的 P0 数据；删除全部数据时，系统明确显示范围、二次确认与最终结果。
3. 用户拒绝 Android 通知权限或关闭同步后，计划、手工记账和会员管理仍可使用，且界面不误报“已同步”或“提醒已开启”。
4. 未确认账单、未授权健康数据、无价格投资和识别失败项目均不会进入正式汇总。

### 13.3 开发前决策

在进入业务开发前，必须形成一份唯一的技术选型结论，明确：本地优先与云同步的关系、账号与设备绑定、端侧/传输/云端加密、密钥管理、同步服务与冲突实现、附件存储、Android 与 Windows 客户端技术路线，以及对 vivo X300 Pro 的通知/Health Connect 实测计划。该决策未完成时，不开始依赖第三方数据源的功能开发。

## 14. 产品策略与发布治理补充

本章不改变既有功能定义；它将 P0 的交付判定、指标、数据边界和后续扩展条件收敛为可执行规则。

### 14.1 北极星与首版核心闭环

**北极星指标：每周至少 4 天完成一次「看今天 → 完成/调整任务 → 记录一笔或处理一个续费提醒」的有效闭环。**

P0 的价值不是“覆盖所有个人生活数据”，而是让用户每天能可靠地知道下一步，并让两类易被遗忘的信息（支出、续费）有可追溯的归处。为避免范围扩张，以下能力被定义为 P0 的核心闭环，其他既列入 P0 的能力按本节的发布判定逐项放行：

| 闭环 | 必经动作 | 可观察结果 | 不成立时的处置 |
| --- | --- | --- | --- |
| 今日安排 | 查看、完成或重排任务 | 当天任务状态清楚；未安排任务有入口 | 不以复杂日历视图替代基础任务可用性 |
| 手动记账 | 在 30 秒内保存一笔支出/收入 | 账单可在列表与月度汇总中追溯 | 不等待支付识别能力 |
| 续费管理 | 新建、查看并处理到期提醒 | 显示下一次扣款、金额、状态与操作记录 | 通知不可用时保留应用内提醒与状态提示 |
| 跨端可信 | 离线编辑后恢复同步 | 显示待同步、已同步或需处理；不静默覆盖 | 任何冲突均不宣称“已同步” |

### 14.2 版本范围的放行规则

1. **P0 必须上线：** 本地可用的任务、今日、手动账本、会员、数据导出/删除、明确的同步与权限状态。任务的日历、便签、番茄钟、倒计时和四象限可与核心闭环并行交付，但不得阻塞核心闭环验收。
2. **P0.5（仅在 P0 稳定后）：** 预算、文件导入、支付通知候选账单；每个数据来源均单独灰度、单独开关、单独验收。
3. **P1：** 贵重物品、投资手工台账、完整分析。投资页面仅表达“记录、汇总、估算”，不表达建议、推荐或收益预期。
4. **P2：** Health Connect 或手动运动记录；目标设备实测未通过时，只保留手动补录和不可用说明。

### 14.3 数据分级、同意与留存

| 级别 | 数据示例 | 默认处理 | 同意与撤回 |
| --- | --- | --- | --- |
| A：一般生产力数据 | 任务、便签、倒计时 | 本地保存并参与用户选择的同步 | 可在设置中关闭同步；本地数据继续可用 |
| B：财务与消费数据 | 账单、账户、会员、资产、投资 | 本地优先；同步前单独说明用途与保护措施 | 可关闭同步、导出和删除；待确认账单不参与统计 |
| C：健康及原始外部数据 | Health Connect 数据、支付通知原文、凭证 | 最小化采集；默认不上传原文 | 单独授权；撤回后停止读取并提供删除入口 |

支付通知原文须定义最短可行留存期：解析成功后仅保留生成候选账单所需字段；解析失败样本仅在用户主动同意的诊断模式中、以脱敏形式短期保存。每一次读取外部数据均应在“数据来源”页说明来源、字段、最近读取时间、关闭方式和替代路径。

### 14.4 指标、质量门槛与复盘节奏

指标仅用于单一用户的产品验证与质量改进，不用于对外营销承诺。上线后按 7 天、28 天两个窗口复盘：

| 维度 | P0 目标或门槛 | 采集原则 |
| --- | --- | --- |
| 闭环使用 | 7 日内至少 4 个有效使用日 | 仅统计必要的匿名事件或端侧聚合；可关闭 |
| 任务效率 | 新建并安排任务的中位耗时 ≤ 60 秒 | 不采集任务正文 |
| 记账效率 | 手动保存一笔账单的中位耗时 ≤ 30 秒 | 不采集金额以外的可识别明细用于分析 |
| 数据可信 | 已入账、待确认、未同步、冲突四种状态可区分 | 以真实状态为准，不能用估计值掩盖 |
| 稳定性 | 关键本地写入成功率 ≥ 99.5%；同步失败可重试且可见 | 在端侧记录错误类别，不上传原始敏感内容 |

若连续两个复盘窗口未达到闭环使用或数据可信门槛，暂停新增自动化数据源，优先修复录入路径、状态表达和同步问题。

### 14.5 体验与内容原则

1. “今天”优先展示行动，分析与历史信息退后；首屏不出现无法立即处理的大图表。
2. 任何金额、估值、收益、同步、识别结果均显示来源、状态和更新时间；不确定时使用“待确认”“估算”而非确定性措辞。
3. 单次录入先收集最小必要字段，其余字段按需展开；避免把全量表单当作快速入口。
4. 失败信息必须说明发生了什么、当前数据是否安全、用户可以做什么；禁止只显示“操作失败”。
5. 品牌、命名、色彩、字体和无障碍规范见《栖序品牌手册》；产品界面不得为追求装饰而降低数字、状态和操作的可读性。
