# 原生安装与验证（0.2 预览）

## 构建与使用

- Windows：`pnpm desktop:build`，需要 Rust/MSVC 与 WebView2。生成 `src-tauri/target/release/bundle/nsis/SELF_0.2.0_x64-setup.exe`。普通用户安装，无 Node 运行时要求。关闭窗口后驻留托盘；托盘可打开或退出；未设开机自启。
- Android：`pnpm android:sync`，随后在 android 目录执行 `./gradlew assembleDebug`（Windows 用 gradlew.bat），需要 JDK 21 与 Android SDK。产物 `android/app/build/outputs/apk/debug/app-debug.apk`。GitHub Actions 已配置相同构建。
- Windows 与 Android 使用同一个前端，但各自有独立的本地账库。已有浏览器数据可先导出 JSON，再导入原生版，或连接同一个 HTTPS 同步服务。
- 在“设置 → 系统提醒”主动开启。拒绝通知权限不影响本地记录。任务在编辑页设置提醒；全天任务上午 9 点；会员到期前 7/3/1 天及当天上午 9 点；倒计时和专注独立提醒。每次最多安排最近的 500 条未来提醒，重新打开或修改数据后刷新队列。
- Android 通过系统保存/分享面板导出，Windows 通过保存对话框导出。导出文件包含明文个人数据。同步密钥与设备令牌单独保存，不放入业务备份。

## 发行边界

这是开发预览安装包：Windows 尚无发行代码签名证书，Android 使用调试签名，未上传应用商店。不同构建环境的 Android 调试签名可能不同，后续覆盖安装前需固定正式签名；如果签名不兼容，先导出备份再卸载，不可直接卸载有未备份记录的应用。

系统通知不是闹钟级准时保证。Windows 应用退出后不提醒；再次运行只补发最近 5 分钟内的过期提醒。Android 使用非精确提醒，系统休眠、省电、强行停止和 vivo 后台限制可能影响送达。没有实现通知动作按钮与免打扰时段。查看系统通知详情并确认已开启，是目标机验收的一部分。

私人同步账户由部署者持有服务所有者令牌，可创建与撤销每台设备的令牌。撤销仅阻止后续请求，不能远程清除已下载数据。没有公开注册、密码找回、密钥轮换或完整账号注销服务。

使用测试数据，记录 Android/OriginOS 版本及每步结果；未执行的项不能标为通过。

1. 安装、首次启动、拒绝通知权限，仍能完成任务、习惯、记账和会员记录；关闭再开数据保留。
2. 开启通知权限，创建 3 分钟后提醒；分别前台、锁屏、切后台验证任务/倒计时提醒。
3. 关闭通知权限，确认界面提示影响；重新允许后重新安排提醒。
4. 省电模式、允许/禁止后台运行、系统重启、强行停止后手动重启分别验证；记录实际延迟，不能据普通浏览器测试推定通过。
5. 与 Windows 安装版连同一 HTTPS 服务，各自断网新增、恢复网络同步；同记录两端修改时逐条选择，双方独立记录保留。
6. 导出并通过系统文件选择器恢复备份，检查任务、倒计时、账单、会员、回收站和历史；核对时区/跨月/退款关联。

Windows 已在本机构建产物安装测试：安装退出码 0，启动界面正常，原生提醒桥接成功创建队列文件；仍未验收锁屏/退出/重启后的通知送达。Android 目前仅构建通过。

原生版不注册 PWA Service Worker，更新安装包直接使用内嵌资源，避免旧缓存覆盖新版本；浏览器版保留离线缓存与手动更新提示。
